## 规则 1｜无激活 = 整行跳过（硬门槛）

```python
activated = [c for c in camps if c["activated"]]
if not activated:
    skips.append({..., "reason": "无激活在跑活动"})
    continue
```

### 判据只看卡片文本

```python
"activated": /激活/.test(bt)
```

**不看按钮文案。** 早期实现额外要求按钮必须是「停止参与」或「修改」，
平台一改措辞（比如改成「管理」），所有在跑的活动都被判成「无激活」，
整行跳过 → 当天全部漏判。

### 为什么这是硬门槛

没有激活 = 这个商品当前没有任何促销在跑 = **没有基准**。
在无基准情况下接受新提案，等于凭空降价，而且大概率降在错误的价位上。

这不是本次任务的范围——项目只做「在已有档位之间择优」，不做「首次定促销价」。

> 实战数据：每轮有 **20～40 条**链接因为「无激活」被跳过。
> 10 店这个数字在 8 轮里从 20 涨到 40，说明活动池在收缩——这是个值得关注的业务信号，
> 但不是脚本 bug。见 [11_Run_Journal.md](11_Run_Journal.md)。

## 规则 2｜基准 = 「激活」∪「已预约」的最小值

### 公式

```python
pool = [c for c in camps if c["activated"] or c["scheduled"]]
base_pool = [("激活" if c["activated"] else "已预约", parse_net(c["txt"])) for c in pool]
base_net = min([n for _, n in base_pool if n is not None], default=None)
```

### 为什么把「已预约」也纳进来

假设一个链接上有这些卡片：

| 卡片 | 状态 | 净收 |
|---|---|---|
| A | 激活 | R$ 110,00 |
| B | 已预约 | R$ 95,00 |
| C | 新提案 | R$ 100,00 |

**只取激活**：base = 110 → C（100）不划算 → 跳过。
**取最小值**：base = 95 → C（100）> 95 → 参加。

哪个对？

B 已经预约了，时间一到就会以 R$ 95 生效。也就是说**你未来必然要接受一档 95 的净收**。
现在平台给一个 100 的提案，接受它意味着把最差的那档从 95 提到 100——**这是净赚**。

如果因为「打不过当前激活的 110」而拒绝，就白丢了一次改善。

> 这条规则是 2026-10-09 15:13 由用户定稿的。早期实现只取激活，
> 在已预约档位更低的情况下会系统性丢弃机会。

### 门槛不变

基准池扩大了，但**规则 1 的「必须至少有一条激活」仍然要过**。
两条规则的交集是：

> 至少有一条激活，且新提案要打得过「激活 ∪ 已预约」里最差的那条。

不是「有了已预约就可以不要激活」。

## 规则 3｜手续费减免绿字，join 和 opt 都要有

平台有时会在卡片上挂绿色小字：

> 我们降低 R$ 3,98 你每笔订单产生的手续费

这是平台侧让利，等于在净收之外白送钱。**没有绿字一律跳过。**

```python
GREEN_PATTERN = r"我们降低|减免\s*R\$|手续费减免|每笔订单"
```

语料里出现过三种表述，用一组关键词命中任意一个。

### 早期 bug：只卡 join 不卡 opt

原实现只在 `kind == "join"` 时检查绿字，`opt` 直接放行。
后果是同一批提案在两条路径上标准不一致——优化的门槛实际上比参加的更低。

2026-10-09 定稿：**两者都必须有。**

> 实战数据：每轮有 **66～143 条**因为「无绿字」被跳过，是所有跳过原因里最多的。

## 规则 4｜join 做卡片层预筛，opt 不做

```python
if is_new and (net is None or net <= base_net):
    skips.append({..., "reason": "净收不高于基准(基线%s)" % base_net})
    continue

# opt 落到这里，不做卡片层预筛
actions.append({...})
```

### 为什么 opt 不预筛

「优化折扣」的真实对比发生在**弹窗里**。弹窗给出「当前档净收」和「新提案净收」两列，
而卡片上显示的净收未必等于弹窗里的「当前」列。

如果卡片层就用 `net <= base` 把 opt 筛掉，会漏掉一批「卡片读数偏低、但弹窗里确实更优」的提案。

代价是 opt 会多开几次弹窗（每次弹窗要等 7s），并在弹窗里被取消。
**这个代价值得付**——因为漏判的代价更高。

> 实战数据：opt 在 8 轮里连续零通过（每次都是「新提案 < 当前」而取消），
> 直到第 9 轮才首次通过一条。**如果因为长期零通过就把它关掉，就会错过这条。**
> 见 [11_Run_Journal.md](11_Run_Journal.md)。

## 规则 5｜限时抢购：折扣不动，数量填仓库数

不属于 analyze 层，属于 joiner 层，但列在这里保持规则完整。

```python
if modal["is_deal"] and modal["has_input"]:
    if modal["warehouse"]:
        fill(warehouse)                 # 有多少上多少
    else:
        keep_default()                  # 读不到 → 不动输入框
```

### 读不到就不动，绝不兜底填 1

早期实现读不到仓库数量时兜底填 `1`。这是错的：

- `1` 个库存的促销活动对曝光毫无意义；
- 平台默认值通常是平台算过的合理值（通常是当前可售库存）。

**保持默认是在信息不足时最安全的选择。**

### 广告勾选框绝对不碰

限时抢购弹窗里有个复选框：

> 通过广告触达更多买家
> 该商品将被添加到广告活动：choubao shaonv

**默认未勾选。脚本永远不碰它。** 勾它等于把一个商品真金白银地拉进广告活动——
这是完全不同的花钱决策，不属于本项目的职责范围。

## 规则 6｜已参加的活动本体不动，「优化折扣」是唯一升级入口

卡片显示「已预约 / 激活」且带「停止参与 / 修改」时 → **不动它**。

但这类卡片旁边常有第二个按钮：**优化折扣**。它的含义是：
平台愿意给你更好的新提案，替换掉当前这一档。

入口识别：

```python
OPT_BTNS = ("优化折扣",)
is_opt = any(b in btns for b in OPT_BTNS)
```

> **早期最严重的漏判**：原实现只认「立即参与」，把「优化折扣」整条漏掉。
> 实测当天输出 0 条 opt 记录——等于每天少了一半的机会面。

## 去重键：一个会静默丢单的设计

```python
def dedup_key(store, rec):
    return (store, rec.get("ident") or rec.get("mlb") or "", (rec.get("camp") or "")[:80])
```

### 早期实现的两套键

| 路径 | 用的键 |
|---|---|
| 跳过 | `(store, mlb, camp)` |
| 参加 | `(store, mlb, bi)` |

两套键混进同一个 `seen` 集合，后果有两个：

**① 同一条活动算不出同一个键** → 去重失效、报告自相矛盾。

**② 无 MLB 的大链接行直接丢单。**

大链接行 `mlb = None`，而 `bi`（卡片索引）在同一行里总是从 0 开始。
于是两个不同商品的「第 0 张卡片」算出**完全相同的键**：

```python
(store, None, 0)   # 商品 A 的第 0 张卡片
(store, None, 0)   # 商品 B 的第 0 张卡片  ← 被判为重复，直接丢弃
```

商品 B 根本不会被处理，**而且不报错、不记账**。

### 现在

统一成一套键，用 `ident`（SKU / `MLB#id 标题`）兜底空 MLB。

**截断长度必须全项目一致**（`CAMP_TRUNC = 80`）。如果不一致，
同一条活动在跳过和参加两条路径上算出的键又会不一样，前面的修复就白做了。
