# 01 · 业务背景：美客多的「报活动」到底在做什么

## 1. 场景

美客多（Mercado Libre）卖家中心的**推广中心**（Promociones）是一个持续推送促销邀请的池子。
平台会把你的商品放进各种活动里，问你要不要参加：你让出一部分价格，平台给你曝光位和搜索权重。

对卖家来说，这不是「参不参加」的问题，而是**在一堆互相冲突的报价里排序**的问题。

### 页面长什么样

```text
商品组（.sc-list-row-group）
├─ 折叠态：一行聚合，带 ▸ 箭头，标题是商品名
└─ 展开态：若干「子链接行」（.sc-list-row），每行对应一个 SKU/MLB
     └─ 每行下挂 2～11 张「活动卡片」（.sc-list-collapsible-row__promotion-box）
          └─ 每张卡片 = 一个独立提案，各自带：
               · 活动名称与时间区间（如 1/10–2/11）
               · 净收款额（R$ 金额）
               · 手续费减免提示（绿色小字）
               · 一个按钮：立即参与 / 优化折扣 / 停止参与 / 修改
```

关键在于**卡片是扁平的、互相竞争的**。同一个商品，平台可能同时给你 8 个提案：
有的净收高但没曝光加成，有的净收低但带手续费减免，有的已经激活在跑，有的已经预约排到下个月。

### 三种卡片状态

| 状态 | 卡片文本含 | 含义 | 可做的动作 |
|---|---|---|---|
| **激活** | `激活` | 这一档正在跑 | 停止参与 / 修改 / **优化折扣** |
| **已预约** | `已预约` | 已占位，等时间到就生效 | 修改 / **优化折扣** |
| **新提案** | 两者皆无 | 平台新给的邀请 | **立即参与** |

`净收款额` 是唯一的可比基准——它已经是扣掉佣金、运费、手续费之后你实际到账的钱。
所有判断都必须落到这个数字上，**不能看折扣率、也不能看标价**。

## 2. 人工做的判断，逐条拆开

一个熟练运营在这个页面上做的事，可以拆成 6 条规则。这 6 条就是这个项目的全部业务逻辑。

### 规则 1｜没有激活 = 不参与（硬门槛）

如果一个链接下**一条激活的活动都没有**，整条链接跳过。

理由：没有激活意味着这个商品当前没有在跑任何促销。在无基准的情况下接受新提案，
等于凭空降价——而且很可能降在错误的价位上。这不是本次任务的范围。

> 注意判据：**只看卡片文本里有没有「激活」两个字**，不要看按钮文案。
> 平台会把按钮从「停止参与」换成别的措辞，用按钮文案判断会在改版当天产生大量误判。

### 规则 2｜基准 = 「激活」与「已预约」净收的最小值

这是本项目**最容易做错的一条**。

直觉做法是「比当前激活那档高就参加」。但从 2026-10-09 起规则调整为：

```text
base = min( 所有「激活」卡片的净收 ∪ 所有「已预约」卡片的净收 )
```

为什么把「已预约」也算进基准池？

- 已预约是**已经占住的档位**，它在选择集里，不是背景噪音；
- 如果已预约的净收比你激活那档还低，说明你把最差的档位当成了底线；
- 拿新的提案去打**其中最差的那条**，只要打得过就是净赚——哪怕它低于当前激活档。

只取激活的后果：已经预约了一条极低价档位时，会有一大批「打得过最差档、但打不过激活档」的提案被
误判为不划算而丢弃。**实际是白丢机会。**

但规则 1 不变：基准池扩大了，**「必须至少有一条激活」这个门槛仍然要过**。

### 规则 3｜手续费减免绿字，join 和 opt 都必须有

平台有时会在卡片上显示绿色小字：

> 我们降低 R$ 3,98 你每笔订单产生的手续费

这是平台侧让利，等于在净收之外白送一笔。**没有绿字一律跳过。**

早期实现只对「立即参与」检查绿字，漏掉了「优化折扣」——
结果是一批本来值得优化的提案被当作普通提案处理，判断标准不一致。

### 规则 4｜有箭头必须展开；展开过的组里，无 SKU 的父行一律忽略

- 无箭头 → 这是一个「大链接」，卡片直接读，SKU 可能为空，汇报标识用 `MLB#<id> <标题>`；
- 有箭头 → 必须展开，逐个子链接行处理。

展开后会出现两类行：

| 行类型 | 有 SKU | 处理 |
|---|---|---|
| 真实子链接 | ✅ | 正常处理 |
| 聚合父行 | ❌ | **忽略**（它的净收是跨变体区间值，不是一条可点的链接） |

对父行点按钮，平台根本不会响应——但如果不忽略，报告里会塞满噪音，而且会占用去重键。

### 规则 5｜限时抢购：折扣不动，只改数量

「限时抢购」类提案的弹窗里多一个数量输入框，页面上写着「仓库：N 个」。

- 读到仓库数量 → 输入框填 N（有多少上多少）；
- **读不到 → 保持平台默认值，不动输入框**（系统弹出几个就是几个）。

早期实现读不到时会兜底填 `1`。这是个错误：`1` 个库存的促销活动对曝光毫无意义，
而平台默认值通常是平台算过的合理值。

### 规则 6｜已参加的活动本体不动，「优化折扣」是唯一升级入口

卡片显示「已预约 / 激活」且带「停止参与 / 修改」按钮时，**不动它**。
但这类卡片旁边常常还有第二个按钮：**优化折扣**。

「优化折扣」的含义是：平台愿意给你一个更好的新提案，替换掉当前这一档。
点开弹窗，里面会并排显示「当前净收款额」和「新提案净收款额」：

- 新 > 当前 → 确认升级；
- 否则 → 取消。

**只认「立即参与」的实现会把整个「优化折扣」入口漏掉**——
2026-10-09 实测，原实现因此 0 条记录，等于每天少了一半的机会面。

## 3. 三个不能碰的边界

| 边界 | 原因 |
|---|---|
| **广告勾选框不碰** | 限时抢购弹窗里有「通过广告触达更多买家」复选框，默认未勾。勾它等于把一个商品拉进广告活动（真金白银）。脚本永远不碰。 |
| **无基准不猜** | 基准读不到时一律跳过并记账，绝不「大概估一个」。 |
| **弹窗复核不达标就取消** | 卡片上写的净收和弹窗里最终的净收可能不一致。凡弹窗读数不达标，一律点取消，不赌。 |

## 4. 每天跑一次的收益结构

以 8 轮真实运行（2026-10-10 ～ 10-17）统计：

| 指标 | 区间 | 说明 |
|---|---|---|
| 单轮判定记录 | 137 ～ 347 条 | 掉登录的轮次会断崖式下跌 |
| 单轮真实参加 | 3 ～ 9 条 | 全部来自「立即参与」侧 |
| 单轮跳过 | 126 ～ 185 条 | 主要是「无绿字」 |
| 全量耗时 | 20m30s ～ 34m11s | 两店串行 |

「优化折扣」侧有个很有意思的观察：**连续 8 轮零通过**，直到第 9 轮（10-17）才首次出现一条通过的提案。
这说明「优化折扣」入口的正确率高但不常开——**不能因为长期零通过就把它关掉**，
行情不是铁板一块。

## 5. 为什么用 CDP 而不是 API

美客多没有公开的促销活动 API（至少没有对普通卖家的）。所有促销提案的状态只存在于**浏览器渲染后的 DOM** 里。

所以整个项目的技术路线是：**紫鸟 CLI 开店铺 → CDP 注入 JS 读 DOM → CDP 真实鼠标事件点按钮**。

这里有个必须记住的约束：**读可以靠 JS，写必须靠真实鼠标事件。**
页面是 React 渲染的，`element.click()` 不会触发 React 的事件处理器。
所有点击都必须走 CDP 的原生鼠标事件（`ziniao-cli page click`）。
